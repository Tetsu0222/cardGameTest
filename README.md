# カードゲーム

遊戯王風の1人用カードゲームです。ブラウザ上でCPUと対戦します。
ルールは2004年頃の環境(シンクロ召喚の導入前)を想定しています。

C# / .NET 10 / Blazor WebAssembly で作っています。ゲームはすべてブラウザ内で動き、サーバー側の処理はありません。

## 特徴

- **ブラウザだけで完結**: ルール判定もCPUの思考もブラウザ内のC#で動きます。静的ファイルとして配信できます。
- **ルールエンジンをUIから分離**: ゲームのルールは`CardGame.Core`にまとめ、画面には書いていません。ルールは画面なしでテストできます。
- **ローカル環境を汚さない開発環境**: .NET SDKをインストールせず、Docker経由でビルド・テスト・起動します。

## 現在できること

| 項目 | 内容 |
|---|---|
| ターン進行 | ドロー → スタンバイ → メイン1 → バトル → メイン2 → エンド |
| 召喚 | 通常召喚・セット(1ターンに1回)。レベル5以上はアドバンス召喚(レベル5・6は1体、7以上は2体をリリース) |
| 表示形式 | 攻撃表示と守備表示の切り替え、反転召喚(1体につき1ターン1回。召喚したターン・攻撃したターンは不可) |
| 魔法 | 通常魔法の発動(手札から、またはセットしてから)。対象を選ぶ効果にも対応 |
| 罠 | 通常罠のセットと発動。相手の攻撃宣言時・召喚成功時に発動できる(セットしたターンは不可) |
| 戦闘 | 攻撃表示・守備表示・裏側守備への攻撃、ダイレクトアタック |
| 手札制限 | エンドフェーズに手札が7枚以上あれば、6枚になるまで選んで捨てる |
| デッキ編集 | 40〜60枚・同名カード3枚までのデッキを組んで保存する(このブラウザに保存。CPUは初期デッキを使う) |
| 勝敗 | ライフが0になる、またはデッキ切れでドローできなくなると敗北 |
| CPU | 損をしない魔法を発動し、罠をセットする。手札が多すぎるときは弱いモンスターから捨てる。攻撃できるときは守備表示から攻撃表示に、耐えられないときは守備表示に切り替える。相手の攻撃・召喚には罠で応じる。相手より強ければ召喚(強くなるならアドバンス召喚)、弱ければセット。一方的に倒せる相手にだけ攻撃 |

### まだできないこと

- 特殊召喚、リバース効果
- 速攻魔法・永続魔法・装備魔法などの通常魔法以外の魔法
- チェーン(罠に罠で応じる、魔法の発動に罠で応じるなど)、効果モンスターの効果
- 攻撃対象がいなくなったときの攻撃の巻き戻し(今は攻撃が中止されます)
- カードの作成(今は cards.json を直接編集します)
- 複数のデッキの保存と切り替え

## 必要なもの

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)

.NET SDKのインストールは不要です。

## 起動方法

リポジトリの直下で次を実行し、ブラウザで http://localhost:5000 を開きます。

```
docker compose up web
```

初回は .NET SDK のイメージとパッケージのダウンロードがあるため、起動まで数分かかります。
止めるときは `Ctrl+C` を押すか、別のターミナルで `docker compose down` を実行します。

コードを変更しても画面に反映されない場合は、`docker compose restart web` で再起動してください。

## 遊び方

1. あなたが先攻です。ドローとスタンバイは自動で進み、メインフェーズ1から操作できます。
2. 手札の下の「召喚」(攻撃表示)か「セット」(裏側守備表示)を押し、光った空きマスをクリックしてモンスターを出します。同じボタンをもう一度押すか「選択をやめる」で取り消せます。レベル5以上のモンスターは、先にリリースする自分のモンスターを必要な数だけクリックしてから、出すマスを選びます(リリースするモンスターのマスにも出せます)。
3. 魔法カードは「発動」ですぐに効果が出ます。対象を選ぶ魔法は、発動後に光ったモンスターをクリックします。「セット」で魔法・罠ゾーンに伏せておき、後のターンにクリックして発動することもできます。
   罠カードは「セット」で伏せておきます。CPUが攻撃や召喚をしたとき、発動できる罠があれば盤面中央で「発動しますか?」と聞かれるので、発動する罠か「発動しない」を選びます。
4. メインフェーズでは、自分のモンスターの下のボタンで表示形式を変更できます(「守備表示に」「攻撃表示に」、裏側なら「反転召喚」)。
5. 2ターン目以降は「バトルフェーズへ」を押し、自分のモンスター、相手のモンスターの順にクリックして攻撃します。相手の場が空なら「ダイレクトアタック」を押します。
6. 「ターン終了」を押すと、(エンドフェーズに手札が7枚以上あれば、先に「捨てる」ボタンで6枚になるまで捨ててから)CPUのターンが1手ずつ進みます。CPUが何をしたかは盤面中央に表示され、攻撃するモンスターと対象は赤く光ります。待たずに進めたいときは「スキップ」を押します。これまでの行動はすべて右側のログで確認できます。

### デッキ編集

対戦画面の右下の「デッキ編集」から開きます。

1. 左のカード一覧で「+」(またはカードをクリック)でデッキに入れ、「−」で外します。上のボタンで種類ごとに絞り込めます。
2. 右側に、デッキの枚数と中身、ルールに合っていない点(枚数が足りないなど)が表示されます。
3. ルールに合っていれば「保存」できます。保存したデッキは次の対戦から使われます(対戦画面の「対戦をやり直す」ですぐに試せます)。

デッキはこのブラウザに保存されます。別のブラウザや端末とは共有されません。

## 開発

### ビルドとテスト

```
docker compose run --rm dotnet dotnet build
docker compose run --rm dotnet dotnet test
```

### ゲーム設定

初期ライフなどのゲームバランスに関わる値は [src/CardGame.Web/wwwroot/appsettings.json](src/CardGame.Web/wwwroot/appsettings.json) で変更できます。

| 設定 | 既定値 | 内容 |
|---|---|---|
| `InitialLifePoints` | 8000 | 初期ライフ |
| `InitialHandSize` | 5 | 初期手札の枚数 |
| `FirstPlayerSkipsFirstDraw` | true | 先攻の最初のターンにドローしない |
| `MaxHandSize` | 6 | エンドフェーズに持っていられる手札の上限 |
| `MinDeckSize` / `MaxDeckSize` | 40 / 60 | デッキの最小・最大枚数 |
| `MaxCopiesPerCard` | 3 | 同じカードをデッキに入れられる最大枚数 |

画面の表示に関する設定もあります(ゲームのルールには影響しません)。

| 設定 | 既定値 | 内容 |
|---|---|---|
| `DuelView:CpuActionDelayMilliseconds` | 700 | CPUの1手ごとの待ち時間(ミリ秒) |

この設定ファイルはブラウザに公開されます。秘密情報は書かないでください。

### カード効果の仕組み

カードの効果は、コードで用意した効果部品を組み合わせてデータで定義します(将来のカード作成機能のため)。

| 部品 | 内容 |
|---|---|
| `DrawCardsAction(枚数)` | カードをドローする |
| `DealDamageAction(量)` | 相手にダメージを与える |
| `GainLifePointsAction(量)` | ライフを回復する |
| `DestroyTargetMonsterAction()` | 対象のモンスター1体を破壊する(対象にできる側を `CardEffect` で指定) |
| `DestroyAllMonstersAction(側, 攻撃表示のみ)` | 指定した側のモンスターをすべて破壊する(攻撃表示だけに絞れる) |
| `DestroyAttackingMonsterAction()` | 攻撃してきたモンスターを破壊する(攻撃宣言時の罠専用) |
| `NegateAttackAction()` | その攻撃を無効にする(攻撃宣言時の罠専用) |
| `DestroySummonedMonsterAction()` | 召喚されたモンスターを破壊する(召喚時の罠専用) |

罠は、発動タイミング(`Trigger`)を指定します。

```csharp
new CardEffect([new DestroyAttackingMonsterAction()], Trigger: TrapTrigger.OpponentAttackDeclared)
```

例:「相手に300ダメージを与え、カードを1枚ドローする」魔法は次のように定義します。

```csharp
new CardEffect([new DealDamageAction(300), new DrawCardsAction(1)])
```

すべてのカードの定義と初期デッキは [src/CardGame.Web/wwwroot/data/cards.json](src/CardGame.Web/wwwroot/data/cards.json) にあります。JSON では部品の種類を `"type"` に書きます。

```json
{ "id": 106, "name": "炎の書", "kind": "Spell",
  "effect": { "actions": [ { "type": "DealDamage", "amount": 300 }, { "type": "DrawCards", "count": 1 } ] } }
```

このファイルはテストでも読み込み、すべてのカードの定義と初期デッキがルールに合っているかを確認しています。

### プロジェクト構成

```
src/
  CardGame.Core/   ルールエンジン(カード、プレイヤー、ターン、戦闘、対戦の進行)
  CardGame.AI/     CPUの思考
  CardGame.Web/    画面(Blazor WebAssembly)
tests/
  CardGame.Tests/  Core と AI のテスト(xUnit)
docs/
  coding_guidelines.md  コーディング規約
```

依存の向きは `Web → AI → Core` です(WebはCoreも直接参照します)。CoreとAIは画面やブラウザに依存しません。

開発に参加する場合は、先に [docs/coding_guidelines.md](docs/coding_guidelines.md) を読んでください。
